# 機制筆記（Mechanism Note）

> 用途：把「要改哪一行」翻成「要動哪個機制」。五行填不出來＝還不能動手。
> 填好後：派工時整段放進 brief；收工時整段放進回報（第四行就是「改動影響聲明」）。
> 專案要求先寫計畫檔時，五行寫進計畫檔當一節，不另寫一份；計畫的測試方式直接用第五行，「不做什麼」直接用結案情境。

## 模板（照抄五行，冒號後填內容）

```
機制筆記
- 系統與職責：
- 症狀所在：
- 現況為何如此：
- 改什麼、牽動誰（改動影響聲明）：
- 怎麼驗整個系統：
```

## 每行怎麼填

1. **系統與職責**：這段 code 屬於哪個系統、該系統對外承諾什麼。寫機制（「X 負責把 A 狀態轉成 B 事件」），不寫檔案（「在 foo.ts 第 120 行」）。
2. **症狀所在**：症狀出現在機制的哪一步。症狀是「太早／太晚」就先翻成「哪個順序被打破」；是「數值不對」就寫「哪個狀態在哪一步被誰改掉」。
3. **現況為何如此**：原始意圖是什麼（先查專案知識庫，再翻 git log／註解／舊版）。查不到就寫「未知」——不假設是設計，也不假設是 bug。查到的原始意圖若知識庫沒有記載，收工時列為知識候選；專案有知識庫提案流程就照它走。
4. **改什麼、牽動誰（＝改動影響聲明）**：動的是哪一層；下游誰依賴這一層（呼叫者、事件訂閱者、共用元件、別款遊戲）；改完整個系統哪些行為會變，不只症狀那一格。列不出下游＝還不能動。修法若出現魔術數字或延遲，寫明它在替哪個狀態條件代打；能判狀態就不用時間。
5. **怎麼驗整個系統**：驗職責不驗症狀——列出該系統每個對外承諾怎麼確認仍成立（不只「症狀消失」那一項）。

## 通用範例（不帶專案名詞）

```
機制筆記
- 系統與職責：結算流程——收到伺服器回包後，依序「停輪 → 播放贏線 → 更新餘額 → 解鎖按鈕」，對外承諾是「餘額更新時畫面上的贏分已播完」。
- 症狀所在：餘額在贏線還沒播完就跳了（「太早」→ 順序「播放贏線 → 更新餘額」被打破）。
- 現況為何如此：git log 顯示餘額更新原本掛在「停輪完成」事件上，當時尚無贏線動畫；贏線動畫後來加進來沒有改掛點。意圖是「停輪就更新」，屬於歷史遺留，不是刻意設計。
- 改什麼、牽動誰（改動影響聲明）：把餘額更新從「停輪完成」改掛到「贏線播放完成」事件。下游：自動旋轉的下一局起轉條件也聽「停輪完成」，不受影響；急停會跳過贏線動畫，必須確認急停路徑仍會發「贏線播放完成」事件，否則餘額永遠不更新。不加延遲，因為「贏線播完」本身就是可判的狀態。
- 怎麼驗整個系統：①一般贏分：餘額在贏線播完才變。②無贏分：餘額照常更新（事件也要發）。③急停：跳過動畫後餘額仍更新。④自動旋轉：下一局照常起轉。⑤斷線還原：還原局的餘額一次到位。
```

## 範圍與總帳（多輪任務）

機制筆記管的是「一次改動想清楚」；任務跨很多輪時，還要管「整件事會不會無限延伸、會不會繞圈」。

1. **開工先定結案情境，定了就封**：列出一套固定的驗收情境（例：哪幾條規格 × 哪幾種輸入 × 哪幾種失敗情況），全過即結案。
   - 中途發現**不在這套情境裡的新類型問題** → 記進專案的常駐待辦檔另開（專案有 `.claude/state/` 就寫 `.claude/state/todo.md`；沒有就問使用者記在哪），不併進本任務、不擴大驗收範圍。
   - 順手發現**與本任務無關的 BUG**（讀程式或驗證時看到的，單輪任務也適用）→ 當下不修，同樣記進常駐待辦檔另開。每條記四件事：位置、現象與影響、查證到哪（已確認／只是疑點）、建議修法。回報時告訴使用者記了幾條、記在哪。
   - 在範圍內的問題才修到底，不留半截。
   - 為什麼：每輪都加新的測試情境，就會一直量到舊程式本來就有的毛病，任務永遠收不了尾，也分不清是在前進還是在繞圈。
2. **每個發現的問題記一行總帳**：

   ```
   #｜問題（使用者看到什麼）｜壞在哪一層／根因｜修法｜關係
   ```

   總帳寫在該任務的進度檔（專案有 `.claude/state/` 就放那裡；沒有就問使用者記在哪），字樣固定才數得出來。
   「關係」只填三種之一：**新機制**／**舊問題重開**（指出是第幾項、為什麼又出現：上次修在末端、修得不完整、判斷錯）／**自己改出來的**（指出是哪一次改動造成）。
   - 回報前先對總帳：同一條規則在不同地方反覆出現 → 上次沒修到源頭，這次改在源頭；同一個參數改了又改 → 寫明每次依據。
   - 被問「是不是在繞圈」時，直接拿總帳回答，不憑印象。

## 常見填法錯誤

- 第 1 行寫成檔名或函式名 → 那是位置，不是機制。
- 第 3 行寫「應該是 bug」或「應該是設計」卻沒有來源 → 改寫「未知」。
- 第 4 行只寫「改 foo.ts」沒列下游 → 等於沒寫。
- 第 5 行只寫「症狀消失」 → 那是驗症狀，不是驗職責。
